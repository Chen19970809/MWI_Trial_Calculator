# KUNPO 1.1.1 性能回归测试

使用 Node.js 24 和 jsdom 26.1.0，执行脚本源码及 DOM MutationObserver。
网络、角色、配装、库存、排刀与战斗经验均为人工构造数据，不连接真实游戏或云端。
这不是浏览器 FPS、CPU 或内存基准测试。

在仓库根目录运行：

```sh
npm --prefix tests/performance ci
npm --prefix tests/performance run test:baseline
npm --prefix tests/performance test
```

基线从 Git 提交 `75ec60c7fb3a9fff06db414810c583411883115e` 读取，无需下载或提交一份重复脚本。
需保留该历史提交（完整克隆，或在浅克隆中先获取该提交）。

两种模式各执行 23 个测试。基线模式通过表示复现原始行为，包括已知问题；
优化模式检查问题修复、已有业务输出与加解密兼容性。
退避上限、国服帧级合并等新增机制在基线模式仅检查其缺失，在优化模式中执行具体断言。

## 本机模拟结果

| 同一场景 | 基线 | 优化版 |
|---|---:|---:|
| 200ms 内失败请求次数（基线人工限制为 5 次） | 5 | 1 |
| 550ms 内库存角标创建次数 | 4 | 1 |
| 600ms 内自身/无关更新触发的排刀重绘 | 2 | 0 |
| 库存显示关闭时 3 条消息触发的汇总次数 | 3 | 0 |
| 连续 2 次读取配装的库存扫描次数 | 2 | 1 |

两次运行均报告 `LIVE_NETWORK_CALLS=0`、`passed=23/23`。
上述事件次数是特定模拟场景的结果，不是实际游戏性能提升百分比。

## 覆盖内容

- 脚本初始化、元数据与内部版本号一致。
- 失败请求 1/2/4/8 秒退避，最多 5 次；手动重置恢复；旧请求响应丢弃。
- 成功请求缓存复用，库存角标自身变更过滤、数量更新/清零、关闭取消待执行回调。
- 排刀与技能输出、无关变更过滤、容器挂载/卡片替换、生活卡文字变化。
- 配装缓存失效、导出强制最新快照、房屋/成就/神龛输出。
- 密钥复用与密码变化、压缩/加密往返、上传保留其他成员和排刀。
- 本地存储更新、WeakSet 提示框集合、Portal 提示框与重新启用、国服定位每帧合并。

本次发布将 `@version` 和 `SCRIPT_VERSION` 同步升级为 `1.1.1`。
